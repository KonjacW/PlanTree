# PlanTree 本地 Web 界面设计

## 目标

在保留现有 stdio MCP 服务与 Codex 插件的前提下，新增一个仅监听本机的 Web 入口。用户可在浏览器中加载、查看和操作演示任务树，不依赖 Codex 是否将 MCP 工具暴露给任务。

## 范围与约束

- 保留 `plugins/plantree/server/src/index.ts` 和现有 MCP 工具名、输入输出契约，不修改其行为。
- Web 与 MCP 共用同一套任务树领域模型、`DemoSession`、编辑、重规划、验证和模拟执行逻辑。
- Web 服务仅监听 `127.0.0.1`，不请求外部网络、不需要账户、不存储密钥。
- 第一版会话只保存在服务进程内存中；进程停止后丢弃状态，重启后恢复预置演示任务。
- 复用现有 React `PlanTreeWindow` 和 CSS，不重写任务树展示与交互。

## 架构

```text
Codex MCP stdio  ──> MCP 适配层 ──┐
                                  ├─ DemoSession / 领域逻辑
浏览器 React 页面 ──> HTTP 适配层 ─┘
```

MCP 适配层保留当前 `DemoSession`，以保障其既有行为与测试不变。HTTP 适配层创建独立的内存 `DemoSession`，避免浏览器中的操作影响未来 MCP 会话，反之亦然。两条入口共享业务逻辑，但不共享进程内的会话状态。

## 服务端接口

新增本地 HTTP 服务，统一返回：

```json
{ "summary": "操作摘要", "snapshot": { "...": "PlanSnapshot" } }
```

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/plan` | 读取当前 Web 会话快照 |
| `POST /api/demo/load` | 加载预置演示任务 |
| `POST /api/nodes/edit` | 接收现有 `edit_node` 等价命令 |
| `POST /api/nodes/:nodeId/simulate` | 模拟执行节点 |
| `POST /api/undo` | 撤销最近一次 Web 编辑 |
| `POST /api/demo/reset` | 重置 Web 演示会话 |

无效 JSON、未知路径和不完整命令返回 JSON 错误及正确 HTTP 状态码。领域层拒绝的操作保持原有错误语义，HTTP 层不在前端猜测状态。

## 前端与数据流

新增一个 Vite 页面入口，启动时请求 `GET /api/plan`，再将快照传给 `PlanTreeWindow`。新增 HTTP `toolCaller` 适配器，将组件已有命令映射到上述 API，并把响应中的服务端快照回填到界面。

现有按钮参数不足以完整支持“添加”和“改写”的用户输入；首版页面仍保留其当前可立即执行的展开、裁剪、模拟、撤销、重置操作。添加和改写将在后续独立变更中增加表单，不在本次扩展中伪造不完整命令。

## 启动与分发

新增一个开发启动命令，顺序执行：构建或提供前端静态资源、启动本地 HTTP 服务、打开默认浏览器至本机地址。运行输出显示实际端口和停止方式。

MCP 的 `.mcp.json` 继续指向 `server/dist/index.js`，不依赖 Web 服务，也不自动启动浏览器。

## 测试

- HTTP 集成测试：加载、读取、展开、撤销、模拟、重置和错误响应。
- 前端适配测试：请求路径与响应快照转换；复用现有 `PlanTreeWindow` 测试覆盖 UI 刷新。
- 回归测试：现有 MCP 服务测试继续通过，证明双入口未改变 MCP 行为。
- 本地验收：启动服务，确认只监听回环地址，并在浏览器中执行至少一次展开与重置。

## 验收标准

1. 即使 Codex MCP 工具未暴露，用户也能在本机浏览器打开并操作任务树。
2. 所有操作后页面使用 HTTP 服务返回的权威快照刷新。
3. 重启服务后演示状态恢复默认；不会创建持久化计划文件。
4. MCP 工具和现有服务端测试的名称、契约与行为保持不变。
