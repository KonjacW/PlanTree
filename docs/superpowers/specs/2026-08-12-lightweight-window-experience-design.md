# PlanTree 轻量小窗体验改版设计

## 目标

将 PlanTree 的 MCP 内嵌小窗定义为唯一的主界面；本地 Web 仅作为同一 React 组件的备用承载。两种入口在视觉、任务树行为和操作语义上保持一致，不发展为全屏或多栏工作台。

改版后的用户应能在约 420 至 560 像素宽的小窗中快速回答四个问题：当前目标是什么、下一步该做哪项、为何被阻塞、刚才操作产生了什么结果。

## 范围与约束

- 继续保留原有 MCP stdio 服务、工具名称与 Web 入口；不修改 `codexzh` 代理或模型设置。
- MCP 与 Web 共享 `PlanTreeWindow`、任务树视觉组件、前端交互状态和操作文案，仅通过 MCP/HTTP 调用适配器获取快照与提交命令。
- 小窗保持单列、轻量、响应式；不实现全屏工作台、跨窗口/文件拖放、持久化、账户或外部网络请求。
- 框选、选中、多选、折叠、键盘导航和节点焦点是本地界面状态；只有结构或任务状态变化才调用 MCP 或 HTTP 服务。
- 拖拽第一阶段只支持同一父节点内排序。移动到其他父节点、依赖连线和跨层拖拽不在本次范围，避免隐式破坏依赖关系。

## 小窗布局

```text
┌ PlanTree                         3 项待办 ┐
│ 修复导入向导在空白配置下崩溃                 │
│ 进度 ███░░░░░  1/6 已完成                    │
├────────────────────────────────────────────┤
│ ▾ 调查崩溃路径                     进行中   │
│   ✓ 收集上下文                               │
│   ○ 整理实施方案                  当前可执行 │
│ ▸ 设计修复方案                 等待调查完成 │
│ ▸ 回归验证                     等待修复完成 │
├────────────────────────────────────────────┤
│ 当前：整理实施方案                            │
│ 依赖：收集上下文（已完成）                    │
│ [完成模拟]  [展开]  [···]                    │
│ 已完成“收集上下文” · [撤销]                  │
└────────────────────────────────────────────┘
```

### 信息层级

1. 顶部仅显示产品名、当前根目标、可执行待办数和完成进度；隐藏面向实现的快照版本号。
2. 主体为可折叠任务树。每个节点固定 40 至 44 像素高，展示状态图标、标题、简短阻塞或执行提示。
3. 底部为随选中节点变化的上下文操作区；最近结果保留为一行可撤销提示，不默认展开审计历史。
4. 节点详情以紧凑抽屉或可折叠区域显示，不在任务树下方长期占据大段高度。

## 交互模型

### 树导航和选择

- 有子节点时显示箭头，点击仅折叠/展开；点击节点其余区域选择节点。
- 初始状态展开根节点、选中路径及最近可执行叶节点所在分支；其余分支保持折叠。
- 单击选择；`Shift` 选择可见节点连续范围；`Ctrl`/`Cmd` 增减选择；点击空白处清空多选。
- 从任务树空白处向节点区域拖动时显示选择框，只选择当前可见节点。框选仅用于查看和后续明确支持的批量操作，不自动改变计划。
- 键盘：`↑`/`↓` 移动焦点，`←`/`→` 折叠展开，`Space` 切换多选，`Enter` 执行主操作，`Ctrl`/`Cmd+Z` 撤销最近服务端编辑。

### 拖拽排序

- 节点左侧提供小型拖拽把手；拖拽不从节点正文开始，避免与选择、框选冲突。
- 仅允许在同一父节点的可见兄弟节点之间调整顺序；目标位置显示插入线，非法目标不提供投放状态。
- 松开后调用新的 `move_node` 命令，返回权威快照；失败时恢复原顺序并显示服务端错误。
- 不支持将节点拖至其他父节点、建立依赖或跨窗口拖入。未来若扩展层级移动，必须以明确“移为子任务”投放标签和影响确认实现。

### 语义化操作

操作区始终只强调一个主按钮：

| 选中状态 | 主按钮 | 辅助内容 |
| --- | --- | --- |
| 无未完成依赖的叶任务 | 完成模拟 | 编辑、裁剪、更多 |
| 有子节点的阶段/目标 | 查看下一项 | 展开/收起、编辑、更多 |
| 有未完成依赖的节点 | 查看阻塞原因 | 跳转至前置节点 |
| 已完成任务 | 重新打开 | 查看操作记录 |
| 多选节点 | 批量操作 | 第一版仅清除选择，批量编辑后续增加 |

- “更多”菜单容纳低频操作：改标题/目标、添加子任务、裁剪。
- 裁剪前显示受影响节点数与名称摘要，提供确认；成功后出现带操作摘要的一键撤销。
- 对阶段节点不再提供会失败的“模拟执行”。前端展示第一项可执行叶节点及跳转动作。
- 服务端成功响应中的 `summary` 直接作为反馈来源；错误响应显示具体错误，不用“操作失败”覆盖。

## 视觉系统

- 使用中性浅灰背景、白色内容面、单一蓝紫主色作为选择和主操作色；不再使用大面积黄色选中背景。
- 状态优先使用图标和文字，颜色只作辅助：完成为勾选，待办为空心圆，执行中为进度点，被阻塞为锁定，失效为警告。
- 减少卡片边框，以间距、浅阴影和分隔线建立层级；焦点节点使用细色条和柔和底色。
- 任务标题支持两行；提示文本一行截断并通过 `title` 或无障碍描述暴露完整内容。
- 触控/鼠标目标不小于 36 像素，键盘焦点具备可见描边，符合轻量窗口的可访问性要求。

## 服务端扩展

### 保持不变

`create_or_load_demo`、`edit_node`、`simulate_execution`、`undo_last_edit`、`reset_demo` 和 `render_plan_tree` 均保留既有输入输出契约。

### 新增 `move_node`

新增独立 MCP 工具和等价 HTTP 接口，用于同一父节点内排序：

```ts
{ nodeId: string; parentId: string; position: number }
```

- `nodeId` 必须是 `parentId` 的现有直接子节点。
- `position` 为目标同级索引，超出范围返回可理解的错误。
- 只更新父节点 `childIds` 顺序、计划版本和审计记录；不改变节点依赖、父子关系或执行状态。
- 作为可撤销编辑写入现有撤销栈。

### 后续独立改动

编辑标题、移动至其他父节点、批量裁剪、批量状态修改和依赖编辑需各自定义输入、影响预览与验证规则，不与本次轻量小窗改版捆绑实现。

## 数据流与一致性

```text
PlanTreeWindow（通用小窗）
  ├─ MCP ToolCaller ──> MCP 工具 ──> DemoSession
  └─ HTTP ToolCaller ─> Web API ──> DemoSession
```

组件从服务端快照派生树结构、可执行项、阻塞提示和进度；折叠、多选、框选与键盘焦点保存在组件本地。每次修改计划后均以服务端返回快照替换界面数据，再保留仍然存在的本地选择。

## 错误处理

- 请求期间禁用同一操作，并在按钮中显示简短加载状态。
- 请求失败保留当前快照和选择，不乐观修改任务结构；反馈展示服务端错误正文。
- `move_node` 失败时恢复拖拽前视觉顺序；不产生局部状态与快照不一致。
- 若选中节点在裁剪或重置后消失，焦点回退到最近可见父节点，最终回退根节点。

## 测试与验收

### 前端测试

- 默认折叠策略、展开/收起与选中路径。
- 单选、多选、框选和键盘导航只影响前端状态。
- 不同节点状态展示正确主操作；阶段节点不会发送模拟执行请求。
- 响应摘要、错误消息、裁剪确认和撤销入口可见且准确。
- 拖拽兄弟节点时生成正确 `move_node` 调用，非法跨父拖放不调用服务端。
- MCP 与 HTTP 调用适配器在同一组件测试场景中呈现一致结果。

### 服务端测试

- `move_node` 能重新排序兄弟节点、递增版本并进入撤销栈。
- 非子节点、未知父节点、越界索引均被拒绝且不改变快照。
- 撤销可完整还原原顺序；现有 MCP 工具测试持续通过。

### 人工验收

在 MCP 可用的 Codex 小窗与 `http://127.0.0.1:5174` 分别加载同一演示快照，核对：布局与交互一致；可折叠和键盘导航可用；可执行任务能完成模拟；阶段节点显示下一步而非错误；同级拖拽排序后可撤销。

## 非目标

- 跨窗口、跨应用或文件拖放。
- 全屏画布、多栏工作台、小地图、自由布局和缩放/平移画布。
- 持久化、协作、登录、远程访问和外部网络。
- 真实代码执行或 LLM 自动规划；执行仍是既有的确定性模拟。
