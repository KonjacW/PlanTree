## ADDED Requirements

### Requirement: 计划有效性检查
系统 MUST 在初始化、每次编辑、每次重规划和每次撤销后运行计划有效性检查。有效计划 MUST 恰有一个根节点、没有父子循环、没有依赖循环、所有主树节点均可从根节点到达，且每个待执行或执行中节点的显式依赖均指向已完成且未裁剪节点。

#### Scenario: 显示有效计划
- **WHEN** 当前计划满足所有有效性规则
- **THEN** 系统显示有效状态和零条问题

#### Scenario: 显示未满足依赖
- **WHEN** 一个待执行节点依赖于已裁剪节点
- **THEN** 系统显示无效状态、标出该节点和依赖原因，并阻止该节点模拟执行

### Requirement: 模拟执行状态
系统 MUST 提供单步模拟执行。只有依赖均已完成的可执行叶节点可从待执行变为执行中再变为已完成；阶段节点 MUST 根据其所有未跳过子节点的终态汇总状态。模拟执行 MUST 不访问项目文件、命令行、网络或外部服务。

#### Scenario: 执行已就绪叶节点
- **WHEN** 用户执行一个所有依赖均已完成的待执行叶节点
- **THEN** 系统依次显示执行中与已完成状态，并更新其祖先阶段的汇总状态

### Requirement: 不可变审计日志
MCP 服务 MUST 为初始化、编辑尝试、成功编辑、重规划、有效性检查、模拟执行和撤销追加时间有序的审计条目。每条条目 MUST 包含事件 ID、时间戳、事件类型、涉及节点 ID、前后计划版本、影响范围、结果和可读摘要；既有条目 MUST 不可被小窗界面操作修改或删除。

#### Scenario: 查看改写的审计链路
- **WHEN** 用户改写一个节点目标并完成局部重规划
- **THEN** 日志按顺序包含改写、影响范围计算、重规划与有效性检查条目
