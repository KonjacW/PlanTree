## ADDED Requirements

### Requirement: 画布框选与多选
系统 MUST 支持从画布空白区域按住鼠标拖拽形成选择框，并选择与选择框相交的节点。单击节点 MUST 替换当前选择；`Shift` 或 `Ctrl/Cmd` 加单击 MUST 追加或切换选择；`Esc` 在没有打开内联工作区或待确认操作时 MUST 清除当前选择。

#### Scenario: 框选多个任务节点
- **WHEN** 用户从画布空白区域拖动选择框覆盖两个或更多任务节点
- **THEN** 系统将这些节点标记为已选中，并在操作条显示已选数量

### Requirement: 单节点快捷键操作
当图形窗口处于活动状态且焦点不在可编辑元素内时，系统 MUST 支持 `P` 开关节点内容、`Enter` 模拟执行单个可执行节点、`E` 展开单个非叶节点、`Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Y` 重做以及 `?` 开关快捷键帮助。系统 MUST NOT 实现 `F` 聚焦快捷键。

#### Scenario: 使用快捷键模拟执行
- **WHEN** 用户只选中一个满足前置依赖的可执行节点并按下 `Enter`
- **THEN** 系统以当前快照版本调用 `simulate_execution`，并按服务端返回快照刷新图形

#### Scenario: 使用快捷键重做
- **WHEN** 图形窗口活动、焦点不在可编辑元素且存在可重做变更时，用户按下 `Ctrl/Cmd+Y`
- **THEN** 系统以当前快照版本调用 `redo_last_edit`，并按服务端返回快照刷新图形

### Requirement: 裁剪确认与多选失败处理
系统 MUST 在用户按下 `Delete` 或点击裁剪操作时显示确认界面，而不是立即裁剪。确认单节点或多节点裁剪时，系统 MUST 排除根节点，并经现有 `edit_node` 裁剪命令逐项提交；如果任一请求失败或发生版本冲突，系统 MUST 停止剩余请求、显示原因并采用服务端返回的最新快照。

#### Scenario: 多选裁剪遇到版本冲突
- **WHEN** 用户确认裁剪多个非根节点且某次裁剪返回版本冲突
- **THEN** 系统停止继续裁剪、以冲突响应的最新快照刷新画布，并提示用户刷新后的结果

### Requirement: 快捷键取消优先级
系统 MUST 使 `Esc` 依次优先处理阻断确认，再收起执行链、快捷键帮助或节点内容工作区；这些界面均关闭后才清除节点选择。焦点位于输入或可编辑内容时，系统 MUST 不截获普通文本编辑所需的快捷键；节点内容编辑器中的 `Esc` 仍 MUST 进入未保存修改保护或关闭编辑状态。

#### Scenario: 取消裁剪确认
- **WHEN** 裁剪确认界面打开且用户按下 `Esc`
- **THEN** 系统关闭确认界面，不调用任务树变更命令，并保留原有选择
