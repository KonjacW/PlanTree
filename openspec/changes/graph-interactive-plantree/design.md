## Context

Plantree 通过同一份版本化 JSON 状态文件向 MCP 数据工具和本地侧栏 Web 提供计划快照。现有 `PlanTreeWindow` 使用层级列表展示节点，并在组件中维护选择、框选和键盘焦点。该形式无法将树层级与 `dependsOn` 依赖同时可视化，也没有针对节点规划提示词的阅读入口。

本变更重做前端呈现、本地交互和执行交接层。它必须继续经现有 MCP/HTTP `ToolCaller` 调用变更命令、由服务端保持权威快照与 `expectedVersion` 冲突保护，并在 Codex 侧栏的有限宽高内工作。产品永久放弃内嵌任务树和内部对话传输；侧栏复制按钮通过版本化请求生成 Markdown 文件对象并放入系统剪贴板。用户明确不需要 `F` 聚焦快捷键，也不需要自由创建连线或全屏工作台。

## Goals / Non-Goals

**Goals:**

- 用 `@xyflow/react` 提供可缩放、可平移、可框选的侧栏任务图。
- 以直观、可访问的自定义节点表达标题、任务状态、短目标、阻塞状态以及树/依赖关系。
- 提供单节点内容详情与结构化编辑、常用快捷键和破坏性裁剪确认，且不绕开后端的编辑协议。
- 以纯函数将 `PlanSnapshot` 转换为图模型和本地提示词，便于单元测试且不改变服务端领域数据。

**Non-Goals:**

- 不将 GraphvizOnline、Graphviz/WASM、远程渲染服务或外部网络加入运行时。
- 不将节点拖动坐标持久化到 JSON，也不允许拖动改变父子结构、同级顺序或依赖边。
- 不加入多用户光标、协同编辑、任意连线编辑、文件拖入、全屏复杂工作台或 `F` 快捷键。
- 不修改 MCP 工具名、HTTP 路由、任务树 JSON 结构、模拟规划逻辑和并发版本规则。

## Decisions

### 1. React Flow 作为主画布

前端增加 `@xyflow/react`，把 `PlanSnapshot` 映射为受控 `nodes` 与 `edges`。选择 React Flow 是因为它直接适配 React 19、支持框选/多选/缩放/平移/自定义节点，并可以限制为轻量画布。AntV X6 的编辑能力超出当前范围，Cytoscape.js 更偏通用网络分析；Graphviz 仅适合自动布局和静态 SVG，缺少本变更要求的交互底座。

### 2. 纯图模型适配器与稳定自动布局

新增纯函数适配层：将父子关系转换为实线边、`dependsOn` 转换为虚线方向边；节点位置由稳定的根向下分层算法计算。布局以 `childIds` 顺序确定同层顺序，避免同一快照在重渲染时跳动。用户拖动只覆盖当前组件内的视觉坐标；服务端更新快照后重新计算位置，并仅保留仍存在节点的本地视觉覆盖。

为保持小窗清晰，节点卡片最多呈现标题、状态与一行截断的目标；根节点与可执行/阻塞状态使用不同的视觉强调，边必须可辨识但不压过节点内容。

### 3. 自动派生提示词与人工覆盖分层

执行提示词由前端和服务端从节点任务、可选方法和可选验收按同一模板纯函数生成，不把节点 ID、类型、状态、父子关系或显式依赖写进正文。用户修改直接保存到节点结构化字段；旧快照仍按原结构加载，无需迁移步骤。

面板只显示结构化内容派生文本；进入编辑后分别修改任务、方法和验收。方法为空与删除全部验收均是有效操作；没有显式验收时，派生文本要求 Agent 自评。遗留 `customPrompt` 字段不覆盖显示或执行，首次结构化 rewrite 时清除。

选中单节点后按 `P` 或点击“节点内容”，在主窗口内的单层工作区展开内容；多选时不生成模糊的批量内容。节点内容、执行链和快捷键帮助复用这一区域并互斥切换，不生成遮罩。面板默认只读并支持复制；点击“编辑内容”后分别编辑任务、方法和验收。空白任务或空白验收不能保存；只有放弃未保存修改使用阻断确认弹窗。节点被服务端更新删除时自动关闭面板。

结构化内容保存复用现有 `edit_node rewrite`：传入 `nodeId`、同步后的 `title`/`objective`、可选 `method` 与 `acceptance`；清除方法使用 `method: null`，清除显式验收使用空数组。操作携带 `expectedVersion`、更新计划与节点版本、写入审计并进入撤销历史。

### 4. 图选择与拖动语义分离

React Flow 的空白画布拖拽框选是主选择机制。单击选中一个节点；按住 `Shift` 或 `Ctrl/Cmd` 单击追加/切换节点；`Esc` 首先关闭帮助或节点内容面板，再清除选择。节点可以拖动改变本地坐标以帮助阅读，但该行为绝不调用 `move_node`。同级排序继续只经现有显式业务操作完成，避免视觉布局与计划语义意外耦合。

### 5. 集中、上下文受限的快捷键

将快捷键处理器绑定到图形窗口，而非全局页面；当焦点位于输入框、可编辑文本或复制提示词区域时不截获文本编辑常用按键。支持的操作为：

| 按键 | 前置条件 | 行为 |
| --- | --- | --- |
| `P` | 单选节点 | 开关该节点内容详情 |
| `Enter` | 图形窗口激活 | 提交一次完整剩余执行链请求 |
| `E` | 单选且非叶节点 | 调用 `edit_node` 的展开操作 |
| `Delete` | 选中至少一个非根节点 | 打开裁剪确认，不立即写入 |
| `Ctrl/Cmd+Z` | 无输入焦点 | 调用 `undo_last_edit` |
| `Ctrl/Cmd+Y` | 无输入焦点 | 调用 `redo_last_edit` |
| `Esc` | 任意 | 依次关闭阻断确认、收起内联工作区、清除选择 |
| `?` | 无输入焦点 | 开关快捷键帮助 |

多选的 `Delete` 需要显示会影响的节点数，并在确认后依次发送现有裁剪命令；若其中一次发生版本冲突或失败，停止后续请求、采用服务端最新快照并提示用户。`Enter`、`E`、`P` 只作用于单选，避免歧义。

服务端在现有会话级撤销栈旁增加重做栈。撤销时将当前快照压入重做栈后恢复撤销栈顶部快照；重做时将当前快照压回撤销栈后恢复重做栈顶部快照。任何撤销后的新编辑或模拟执行都会清空重做栈；重置同时清空两个栈。新增 `redo_last_edit` MCP 工具与 `/api/redo` HTTP 路由，沿用 `expectedVersion` 和冲突快照恢复规则。服务端重启后撤销和重做历史均按现有会话语义清空。

### 6. 侧栏编辑与 Codex 等待交接

`PlanTreeWindow` 或其替换组件继续接收现有 `plan` 与 `toolCaller`，并在所有变更调用中注入 `expectedVersion`。HTTP 409 和 MCP 冲突继续采用服务端最新快照刷新画布、保留仍存在的选择和局部视觉位置。复制按钮提交 `planId` 与 `snapshotVersion` 后，服务端生成包含完整剩余任务提示的 `plantree-prompt.md`，并通过 Windows `FileDropList` 写入剪贴板。不注册 MCP App、内嵌任务树资源或对话恢复桥。

### 7. 轻量实现与集中监测点测试

实现只扩展现有 `PlanNode`、`PlanEditor`、`DemoSession`、`edit_node`、`ToolCaller` 和内联工作区，不引入新依赖、独立内容仓库、额外状态管理库或重复的历史实现。执行文本派生保持为独立纯函数；重做行为集中在 `DemoSession`，MCP 与 HTTP 只做薄协议映射。

测试采用少量高价值监测点集中覆盖，不在多层重复测试同一业务规则：

- 纯函数监测点：结构化内容到执行文本的派生和空白校验。
- 领域监测点：提示词保存与清除的版本变化、审计和节点字段结果。
- 会话监测点：撤销、重做、新分支清空 redo、重置清空历史与版本冲突。
- 协议监测点：各保留一组 MCP/HTTP 映射测试，确认 `expectedVersion`、`redo_last_edit` 和 `edit_node prompt` 参数完整。
- UI 监测点：一组集成测试覆盖编辑、保存、恢复、未保存确认、过期提示和 `Ctrl/Cmd+Y`；不重复验证 React Flow 已有视觉与选择行为。

## Risks / Trade-offs

- [React Flow 在侧栏高度有限时出现拥挤] → 首次渲染执行适配视图、限制节点信息密度、提供最小缩放范围与窄窗口样式。
- [自动布局覆盖用户刚拖动的位置] → 视觉位置只在同一 UI 会话内保存；服务端结构变化后有意识地回归确定性布局，避免假装已持久化。
- [依赖边和树边交叉造成噪声] → 使用不同颜色、线型、标记和简短图例；只显示直接依赖。
- [快捷键与 Codex 宿主或文本输入冲突] → 仅在画布窗口激活且非可编辑元素时处理，并为所有操作保留可点击入口。
- [多选裁剪产生部分成功] → 逐项执行并在首个失败/冲突时停止，始终显示服务端返回的最新状态和结果说明。
- [新增依赖增大打包体积] → 仅引入核心 `@xyflow/react`，不引入额外布局或图标库；通过生产构建大小与侧栏冒烟测试评估。
- [结构化节点修改与执行文本不一致] → UI 与执行链都从服务端返回的同一节点字段重新派生，禁止自由文本覆盖。
- [撤销后继续编辑导致重做分支含义不明确] → 任意新变更清空 redo 栈，采用标准线性历史语义。

## Migration Plan

1. 新增依赖、图模型和单元测试，但保留现有 `ToolCaller`、数据协议和列表实现直到图形组件测试通过。
2. 用图形组件替换主展示区域，将现有详情/反馈迁移为抽屉、操作条和轻量控制栏。
3. 验证侧栏 Web 一次点击后可在目标 Codex 对话粘贴 `plantree-prompt.md`；发生问题时保留 MCP 数据工具，不回退到内嵌任务树或内部传输。
4. 仅在组件、快捷键、版本冲突和生产构建验证通过后移除不再使用的列表树样式与测试。
